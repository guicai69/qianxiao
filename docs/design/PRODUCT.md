# PRODUCT.md — 羽毛球馆预约管理系统 · 界面设计锁

> 这份文件锁的是**不许漂移的东西**（配色、字体、规则）。构建记录（每次做了什么、要避开什么）在 `.finesse/log.json`，两者分工不同，不要混。

- **改版日期**：2026-09-19
- **分支**：`ui/finesse`
- **灵感来源**：[motionsites.org](https://motionsites.org/) 那一类"获奖级动效站"，即：首屏要有**跟内容有关的真动效**，不是背景装饰。
- **技术约束**：Vue 3 + Element Plus 2.14 + Vite，不引入任何新的运行时依赖（零 GSAP、零 Three.js）。

## 1. 三档 register（同一个项目里有三种页面，判断标准不同）

| 档位 | 页面 | 目标 | 动效强度 | 密度 |
|---|---|---|---|---|
| **brand** 品牌门面 | 会员首页 `Home.vue`、登录 `Login.vue`、注册 `Register.vue`、404 | 让人记住，视觉本身就是产品 | 7 | 4 |
| **commerce** 交易流程 | 场馆列表 `VenueList.vue`、场馆详情 `VenueDetail.vue` | 看得清、比得了、下得去单 | 3 | 7 |
| **product** 后台 | `AdminLayout` + 管理端 7 个表格页 + 两个看板 | 天天用不累 | 2 | 8 |

**硬规矩**：brand 那套（颗粒、暗底、巨字号、球场 3D）**不许**流进 product 档。后台不碰导航习惯、不碰表格行为、不碰状态色语义（红=坏、绿=好）。

## 2. 隐喻

**胶片接触印相表**。球场本来就是一块带线框的矩形，一排球场就是一张印相表，编号、格线、逐格挑选，正好就是"选场地"这个动作本身。
所以 `01–05` 这个编号是**有理由的**，它跟着区走（天河 01 / 海珠 02 / 白云 03 / 番禺 04 / 越秀 05），不是装饰。

## 3. 颜色（唯一真源：`src/styles/tokens.css`）

| 角色 | 纸面 paper | 球馆 hall |
|---|---|---|
| 页面底 | `#eef1ea` | `#0b100e` |
| 面板 | `#fbfcf9` | `#131a16` |
| 正文墨色 | `#14201a` / `#3d4a43` / `#6e7d74` | `#eef1e9` / `#b8bfb1` / `#8d968a` |
| 主色（顶灯琥珀） | `#a85a1e` | `#e8a33d` |
| 副色（场地漆绿） | `#2f6b4f` | `#5fd3b2` |
| 语义 | 成功 `#2f7a55` · 危险 `#c0453c` · 警示 `#b77a16` | 成功 `#3fcb86` · 危险 `#ff6156` · 警示 `#e8a33d` |
| 后台侧栏 rail | — | `#141a16` |

规则：
- **不用纯白 `#fff`、不用纯黑 `#000`**。所有中性色朝主色温度偏 2 个点。
- **主色锁死**：琥珀只做一件事（主操作 / 强调数字）。不在同一个页面里冒出第二个强调色。
- 亮底上的琥珀压深到 `#a85a1e` 是为了白字达到 4.5:1 对比度，**不要为了好看改浅**。
- 亮/暗两个平面靠 `[data-plane="hall"]` 切换，所有 Element Plus 变量都接到令牌上，所以组件会自动跟着平面走。

## 4. 字体与数字

- **不加载任何网络字体**（答辩现场断网也不掉字）。中文用系统栈：`PingFang SC / Microsoft YaHei / Noto Sans SC`。
- **数字（金额、时间、编号、手机号）一律 monospace + `tabular-nums`**，加 `class="mono"`。价格对齐是这类系统最容易显得专业的地方。
- 标题 800/900 配负字距（`-0.02 ~ -0.035em`），正文 300/400。极端字重对比是这套排版的骨架。

## 5. 动效预算（硬上限）

| | 上限 | 说明 |
|---|---|---|
| 重头戏（需要引擎的） | **1 个** | 首屏的球场：R6 零依赖 CSS 3D + R2 原生滚动驱动镜头推进 |
| 总拍数 | **4 拍** | 首屏（空间/镜头）· 滚动（图像显影）· 交互（状态过渡）· 收尾（排版浮起） |
| 同一家族 | 每拍一个不同家族 | 两拍同族算重复 |
| 跑马灯 | 1 条 | 本项目没用 |

必守：
- `prefers-reduced-motion: reduce` 时**不是关掉，是给一张排好的静帧**（镜头停在构图最好的一帧，线已画完，格子全部显影）。`base.css` 里有兜底，`brand.css` 里的动画都写在 `no-preference` 媒体查询里。
- 只动 `transform` / `opacity`。
- 页面**去掉全部动效也完整可读可用**（滚动时间线用 `@supports` 包着，不支持就是静态帧，不会白屏）。

| 页面 | 家族 |

## 7. 反例（明确不做）

- 深色底 + 紫色辉光 + 玻璃拟态卡片（AI 做"炫酷官网"的固定落点）
- 米色纸感 + 铜金衬线 + 牛皮纸纹理（上面那个的反面，同样是被用烂的"高级感"）
- 每个标题上方一行全大写英文小字
- `图标 + 标题 + 两行字` × N 的重复卡片网格（后台 KPI 曾经就是 9 张一模一样的卡）
- 假精确数字（`92%`、`4.1×` 这种编出来的百分比）
- 文案里用破折号「——」做装饰

## 11. 改版后追加的两项改动（已落地并验证）

1. **游客可看场馆**：后端新增只读动作 `GET /api/venues/public/`（`AllowAny`，只返回启用中的场馆基础信息，**不含**场地/时段/价格明细）。
   注意坑：`VenueViewSet.get_permissions()` 会覆盖 `@action(permission_classes=...)`，所以新动作必须在 `get_permissions()` 里登记，否则会掉进最后那条 `IsAdminOrReception`。
   边界已复核：`/venues/`、`/venues/{id}/`、`/venues/{id}/availability/`、`/courts/`、`/time-slots/`、`/bookings/my/` 未登录仍是 401。
   前端：未登录时首页改调 `venueApi.publicList()`，格子 CTA 变「登录后选时段」并跳登录页；接口异常时退回"锁住的印相表"。
2. **管理员可进操作台**：`/reception` 路由 `meta.roles` 加了 `admin`，`AdminLayout` 的菜单对管理员也显示「操作台」。
   依据：后端 `check_in` / 收款用的就是 `IsAdminOrReception`，权限本来就允许；改完一个账号即可演示"看数据 + 到店核销"整条链路。
