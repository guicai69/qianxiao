# 预订/支付正确性与业务规则完善

## Problem Statement

现有系统在预约、取消、收款、可预约展示等环节存在正确性缺口：并发下同一场地时段可被双写；未支付订单永不过期而锁死时段；已支付订单取消一律全额退款（无政策）；管理端「收款确认」不留支付记录；会员端可预约状态只反映本人订单（看不到他人占用）；签到不校验日期；营收口径缺少充值/退款指标。

## Solution

补齐上述正确性与业务规则，使预约冲突、取消退款、现金收款、可预约展示、签到、统计全部符合真实业务语义，并为关键规则补充 API 级回归测试。

## User Stories

1. 作为会员，我希望同一场地同时段无法被两人重复预约，避免到店冲突。
2. 作为会员，我希望未支付订单 15 分钟后自动失效并释放时段，避免他人无法预约。
3. 作为会员，我希望在开场前 2 小时以上可自助取消已支付订单并全额退款。
4. 作为会员，我希望在开场前 2 小时内取消需联系管理员/前台并扣 20% 手续费。
5. 作为管理员/前台，我希望线下收款确认能生成现金支付记录（审计留痕）。
6. 作为会员，我希望在选场页看到全局真实占用（不含他人隐私信息）。
7. 作为管理员/前台，我希望签到仅能在预约当天完成。
8. 作为会员，我希望充值只能使用微信/支付宝。
9. 作为管理员，我希望数据看板展示充值/赠送/退款总额。

## Implementation Decisions

- **并发防双写**：新增 `occupancy_key` 唯一键（已支付 = court-date-slot，其余为 NULL），MySQL 唯一索引允许多个 NULL；下单在事务内锁场地行并重查冲突。
- **pending 超时**：15 分钟未支付自动取消；惰性触发（可预约查询/下单前）+ 管理命令兜底。
- **取消政策**：距开场 >2h 免费全额退款；≤2h 且未开场退 80%（扣 20% 手续费）；已过开场不退。会员仅 >2h 窗口内可自助取消。
- **退款**：一律退回余额；按实付金额（折后）计手续费；手续费保留在累计消费中（新增 `fee_amount`，累计消费 = 已支付订单 + 已取消订单手续费）。
- **收款确认**：新增 `cash` 支付方式，`confirm_cash` 按订单全额、不可改，生成现金支付记录。
- **可预约展示**：新增只读 `availability` 接口，仅返回被占用 `court_id + time_slot_id`。
- **签到**：日期必须等于预约日期。
- **统计**：营收仍只计已支付预约；新增充值总额（本金）/赠送总额/退款总额。

## Testing Decisions

- 主接缝：DRF API 集成测试（APITestCase + force_authenticate），断言 HTTP 外部行为。
- 次接缝：模型单元测试（累计消费含手续费）。
- 好测试只验证外部行为，不依赖实现细节；时间相关逻辑用 mock 固定 now。

## Out of Scope

- 手续费暂不计入营收。
- 场馆图片、营业日历/闭店日等体验功能本轮延后。
- 退款不按原支付渠道原路退回（统一退余额）。
